## 1. 目标

- **D14**：健康状态与组配置分离，检查组每轮实时读取，选择逻辑正确（DIRECT 真实探测、REJECT 排除）。
- **D16**：订阅刷新并发一致性（ActiveMember 统一 setter、回退分支与成功分支一致）。
- **D24**：SSH 连接池引用计数 + singleflight + 锁外握手。
- **ctx 贯穿**：所有 dialer 与链内跳支持取消/超时，health check 预算真正生效。
- **D25**：P2P 最低版本协商 + 能力位；版本不满足时保持周期探测。

## 2. 设计要点

### 2.1 健康检查（D14）

- 运行态表：`组名 + 节点名 → {alive, latency, lastCheck, failCount}`，内存存储，不落库。
- 每轮从当前配置实时取组，不写回组配置（不再覆盖用户改动、不再复活已删组）。
- best 在存活节点中按延迟选；load-balance 只在存活节点中分配；REJECT 永远排除。
- DIRECT 参与选择但走真实探测得到延迟（不再用 0 占位）。
- 全局 ctx + 全局 deadline；每节点使用自身 `MaxDialTimeout`（htunnel 35s，其余 5s）。
- 组/节点删除时清理运行态条目。

### 2.2 订阅刷新（D16）

- 所有 `ActiveMember` 写入走 `SetActiveMember`（持 `selMu`）。
- 网络失败走 DB 回退时与成功分支执行相同的组重建与 ActiveMember 校验。

### 2.3 SSH 池（D24）

- 连接引用计数：被引用期间不回收；归零后进入空闲回收。
- 同目标单飞建连（singleflight），避免并发重复握手。
- TCP/TLS/认证握手移出全局池锁。

### 2.4 ctx 贯穿

- 所有 dialer 实现 `DialContext`；链内下一跳传递 ctx。
- SSH 使用可取消的通道打开；htunnel/hysteria2 实现真实 deadline（循环内检查）。
- 健康检查使用 `ChainDialContext` + 每节点预算。

### 2.5 P2P 版本协商（D25）

- 握手交换版本范围与能力位，取双方可用最低版本。
- 新帧类型按对端能力启用；版本不满足时保持周期探测与重连，不永久拉黑。

## 3. 验收

- 健康检查：断网/慢节点下组选择正确；重启后重新检查；无 goroutine 泄漏。
- 订阅：并发改成员/刷新不丢配置。
- SSH：长连接不再被空闲回收掐断；并发拨号不再串行。
- ctx：取消能在各协议握手阶段生效。
- 版本：滚动升级期间新旧版本可共存并保持探测。
- 三平台编译通过；相关测试通过。
