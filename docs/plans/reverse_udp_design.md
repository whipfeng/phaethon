# 反向 UDP 通道设计文档

## 角色定义

| 角色 | 说明 |
|------|------|
| **客户端** | 真正用户，curl/浏览器 |
| **代理端** | 公网机器，跑 Registry + Server + 入口映射 |
| **反向端** | NAT后，主动向外建连，被代理端拉取 |
| **中间代理节点** | 反向端→代理端之间的链路（trojan→socks5） |

## 拓扑

```
客户端 → 代理端(公网) ←反向连接← 反向端(NAT后)
                ↑                    │
          同一进程(本地测试)    中间代理链(trojan→socks5→...)
```

## 设计一：一次性探测（已废弃）

**问题**：10秒阻塞等探测包，NAT过期后失联，超时由UDP层自己判。

```
┌──────────┐                    ┌──────────┐
│  代理端   │                    │  反向端   │
│          │   TCP: cmd(0x04)    │          │
│          │───────────────────> │          │
│          │   TCP: Port D addr  │          │
│          │───────────────────> │          │
│          │   TCP: session key  │          │
│          │ <────────────────────│          │
│          │                    │          │
│  阻塞!   │   等UDP探测包...     │          │
│  ReadFrom │                    │          │
│  (10s超时)│   发0x00探测        │          │
│          │ <────────────────── │          │
│          │   更新remoteAddr    │          │
│  返回pc  │                    │          │
│          │                    │          │
└──────────┘                    └──────────┘

缺陷:
- DialPacket() 阻塞最多10s，超时整个会话废掉
- 探测是明文0x00，无认证
- 只探测一次，NAT地址过期后失联
- 超时由UDP层自己判断，职责不清
```

## 设计二：TCP传地址 + 加密心跳（当前实现）

**改进**：TCP握手传初始地址，不再阻塞；加密心跳保活NAT；但仍有readyCh等待问题。

```
┌──────────┐                    ┌──────────┐
│  代理端   │                    │  反向端   │
│          │                    │          │
│ TCP握手:  │   cmd + Port D addr│          │
│          │ ─────────────────> │          │
│          │   session key       │          │
│          │ <───────────────── │          │
│          │   tunnel local addr│          │
│          │ <───────────────── │          │
│          │                    │          │
│ 返回pc   │  启动chainReader   │  立即发第一个心跳
│ (异步)   │  启动tcpKeepalive  │  (加密帧 ATYP=0xFF)
│          │                    │ ────────> │
│          │                    │           │
│ 等readyCh│  收到心跳          │  每10s循环
│ (阻塞)   │  更新remoteAddr    │           │
│ close()  │  close(readyCh)    │           │
│          │                    │           │
│ 返回!    │                    │           │
│          │                    │           │
│ tcpKA    │  60s读TCP         │  每10s心跳
│ 超时关   │  断开→Close()     │           │
└──────────┘                    └──────────┘

遗留问题:
- 第一个心跳要等10s（Ticker首次触发），而readyCh也等10s——竞态
- readyCh阻塞还是让DialPacket有等待逻辑，不够干净
- 超时最终靠tcpKeepalive兜底，但中间有冗余等待
```

## 设计三：TCP控制面管一切（目标方案）

**原则**：
- **TCP 控制面**：握手、传地址、通知 READY、超时判定、关闭通道
- **UDP 数据面**：只管收发数据帧 + 收到心跳更新 remoteAddr
- **UDP 层不碰超时**，超时 = TCP 断了 = 一切关闭

### TCP 握手协议

```
步骤  方向        内容                      格式
────  --------  ------------------------  ------------------
1     代理→反向    UDP_CHANNEL 命令          [0x04]
2     代理→反向    代理端 Port D 地址         "host:port\n"
3     反向→代理    Session Key (32字节hex)    "64个hex字符\n"
4     反向→代理    反向端 tunnel 本地地址    "host:port\n"
5     反向→代理    READY 确认                "READY\n"

总耗时: 几毫秒级 (本地回环) 或 RTT (远程)
返回条件: 收到 "READY\n" 后立即返回 pc，不阻塞等 UDP
```

### UDP 心跳协议

```
方向: 反向端 → 代理端 (单向)
间隔: 首次立即发送，之后每 10 秒
格式: AEAD 加密后的 Reverse UDP 帧

明文帧: [0x00 0x00] [ATYP=0xFF]
密文帧: Seal([0x00 0x00 0xFF]) ≈ 18 字节

接收处理 (代理端 chainReader):
  crypto.Open(密文) → ParseReverseUDPFrame → ATYP==0xFF?
    → 是: 更新 remoteAddr = srcAddr (NAT映射地址)
    → 否: 解析出 target+payload → 送 dataCh → ReadFrom 返回给上层
```

### 生命周期管理

```
正常流程:
  TCP 握手成功 → 返回 pc → 数据收发...
  TCP Keepalive 60s 无数据 → Close() → 清理所有资源

异常流程:
  TCP 握手某步失败 → cleanupBoth → 返回 error → 上层报错
  TCP 握手超时 → tcpKeepalive 检测到 → Close()
  中间代理节点不通 → UDP 心跳发不出去 → 但不影响(超时仍由TCP判定)
  客户端断开 → 上层调 pc.Close() → 关 TCP → 反向端检测到断开
```

### 安全性

```
攻击场景              防御措施
--------------------  ----------------------------------------
伪造心跳包            没有 session key，crypto.Open() 直接拒绝
伪造数据帧            同上，AEAD 认证失败静默丢弃
重放旧心跳/数据帧      AEAD nonce 递增，重放解密失败
明文探测(设计一的问题)  所有帧都走加密，不存在明文路径
按大小区分(临时方案)   改用 ATYP 类型字段，语义清晰
```
