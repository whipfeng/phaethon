# 节点级互相印证处理传播延迟示例

## 场景
- X 和 Y 是邻居
- Z 是中间节点，从 X 和 Y 接收 gossip
- X 和 Y 的 gossip 在不同时间到达 Z

## 时间线

```
时间 T0: 初始状态
┌─────────────────────────────────────┐
│ 节点 Z 的状态                        │
├─────────────────────────────────────┤
│ peers[peerX].ClaimedSubnets = []    │
│ peers[peerY].ClaimedSubnets = []    │
│                                     │
│ bestClaims = {}                     │
│ validatedClaims = {}                │
└─────────────────────────────────────┘

时间 T1: Z 收到 X 的 gossip（X 声明 Y 是邻居）
┌─────────────────────────────────────┐
│ 原始数据（存储在 peers 中）           │
├─────────────────────────────────────┤
│ peers[peerX].ClaimedSubnets = [     │
│   {nodeID: "X", neighbors: [Y]}     │  ← X 的 claim
│ ]                                   │
│ peers[peerY].ClaimedSubnets = []    │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│ 构建 bestClaims                     │
├─────────────────────────────────────┤
│ bestClaims = {                      │
│   "X_subnet": {nodeID: "X", ...}    │  ← 从 peerX 读取
│ }                                   │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│ 节点级互相印证                       │
├─────────────────────────────────────┤
│ 检查 X 的 claim:                    │
│   X 声明 neighbors=[Y]              │
│   → 检查 Y 是否也声明 X？            │
│   → nodeIDToClaim["Y"] = ???        │
│   → 不存在！                         │
│   → 验证失败 ❌                      │
│                                     │
│ validatedClaims = {}                │  ← X 被过滤掉
└─────────────────────────────────────┘

结果：X 的 claim 被过滤，拓扑中看不到 X


时间 T2: Z 收到 Y 的 gossip（Y 声明 X 是邻居）
┌─────────────────────────────────────┐
│ 原始数据（存储在 peers 中）           │
├─────────────────────────────────────┤
│ peers[peerX].ClaimedSubnets = [     │
│   {nodeID: "X", neighbors: [Y]}     │  ← X 的 claim（仍在）
│ ]                                   │
│ peers[peerY].ClaimedSubnets = [     │
│   {nodeID: "Y", neighbors: [X]}     │  ← Y 的 claim（新到）
│ ]                                   │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│ 构建 bestClaims                     │
├─────────────────────────────────────┤
│ bestClaims = {                      │
│   "X_subnet": {nodeID: "X", ...},   │  ← 从 peerX 读取
│   "Y_subnet": {nodeID: "Y", ...}    │  ← 从 peerY 读取
│ }                                   │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│ 节点级互相印证                       │
├─────────────────────────────────────┤
│ 检查 X 的 claim:                    │
│   X 声明 neighbors=[Y]              │
│   → 检查 Y 是否也声明 X？            │
│   → nodeIDToClaim["Y"] = ✓ 存在     │
│   → Y.neighbors 包含 X？ ✓ 是       │
│   → 验证通过 ✅                      │
│                                     │
│ 检查 Y 的 claim:                    │
│   Y 声明 neighbors=[X]              │
│   → 检查 X 是否也声明 Y？            │
│   → nodeIDToClaim["X"] = ✓ 存在     │
│   → X.neighbors 包含 Y？ ✓ 是       │
│   → 验证通过 ✅                      │
│                                     │
│ validatedClaims = {                 │
│   "X_subnet": {...},                │  ← X 现在有效
│   "Y_subnet": {...}                 │  ← Y 现在有效
│ }                                   │
└─────────────────────────────────────┘

结果：X 和 Y 的 claims 都通过验证，拓扑中看到 X↔Y


## 关键机制

1. **原始数据持久化**：即使 claim 验证失败被过滤，原始数据仍保留在 `peers[].ClaimedSubnets` 中

2. **每次重新验证**：每次构建拓扑/路由时，都从原始数据重新构建 `bestClaims`，然后重新验证

3. **延迟处理**：
   - T1 时刻：X 的 claim 验证失败 → 过滤
   - T2 时刻：Y 的 claim 到达 → 重新验证 → X 和 Y 都通过

4. **最终一致性**：一旦双向 gossip 都到达，两个方向的 claims 都会通过验证
