# Mesh IPIP 封装与智能选路 - 开发任务

## 概述

本任务文档拆解 `mesh_ipip_smart_routing.md` 设计文档的三阶段实施计划。

## Phase 1: IPIP 封装（优先级：P0）

### 任务 1.1: 修改出站包封装逻辑
**文件**: `mesh/mesh.go`
**描述**: 
- 修改 `HandleOutboundPacket`，所有 mesh 流量封装成 IPIP
- 源节点查拓扑，找到目标 nodeID
- 封装 IPIP：外层 src=localEIP, dst=targetEIP
- 查路由到 targetEIP，选下一跳 peer，发送封装包

**验收标准**:
- [ ] 所有 mesh 出站包都封装成 IPIP
- [ ] 外层目标地址是目标 nodeID 的 EIP
- [ ] 能通过现有路由到达目标节点

### 任务 1.2: 修复静态路由查路逻辑
**文件**: `mesh/mesh.go`
**描述**:
- 修复第 719-726 行：用 subnet 或 EIP 查路由（而不是 VIP）
- 语义更清晰：我要发送数据到这个网段
- 中间节点不需要特殊处理（还是按网段路由）

**验收标准**:
- [ ] 用 `egressEIP` 或 `egressSubnet.IP` 查路由
- [ ] 不再用 `egressVIP` 查路由
- [ ] 功能正常

### 任务 1.3: 修改中间节点转发逻辑
**文件**: `mesh/mesh.go`, `mesh/ipip.go`
**描述**:
- `HandleMeshFrame` 识别 IPIP 包（protocol=4）
- 提取外层目标地址
- 查路由表找到对应的 peer（按网段路由，无需特殊处理）
- 转发封装包（不解封装）

**验收标准**:
- [ ] 中间节点能识别 IPIP 包
- [ ] 按外层目标地址的网段转发
- [ ] 不解封装内层包

### 任务 1.4: 实现目标节点解封装
**文件**: `mesh/mesh.go`, `mesh/ipip.go`
**描述**:
- 目标节点检查外层目标 == 自己的 EIP
- 调用 `Decapsulate()` 剥离外层 header
- 处理内层原始包（走现有逻辑）

**验收标准**:
- [ ] 目标节点能正确解封装
- [ ] 内层包能被正确处理
- [ ] 端到端通信正常

### 任务 1.5: 测试验证
**环境**: QG + JF
**描述**:
- 部署 Phase 1 代码到 QG 和 JF
- 测试 mesh 节点间通信
- 测试域名访问
- 验证 IPIP 封装/解封装正常

**验收标准**:
- [ ] QG ↔ JF mesh 通信正常
- [ ] 域名访问正常（如 gg.phn, jf.phn）
- [ ] 日志显示 IPIP 封装/解封装

## Phase 2: 链路质量监控（优先级：P1）

### 任务 2.1: 实现 PeerQuality 数据结构
**文件**: `mesh/quality.go`（新建）
**描述**:
- 定义 `PeerQuality` 结构体（rtt, packetLoss, lastUpdate）
- 实现滑动窗口平均（RTT）
- 实现丢包率统计

**验收标准**:
- [ ] 能存储和更新 RTT
- [ ] 能存储和更新丢包率
- [ ] 滑动窗口正常工作

### 任务 2.2: 实现探测包协议
**文件**: `mesh/probe.go`（新建）
**描述**:
- 定义 `ProbeMsg` 和 `ProbeReply` 消息格式
- 实现探测包发送逻辑
- 实现探测包接收和响应逻辑

**验收标准**:
- [ ] 能发送探测包
- [ ] 能接收探测包并回复
- [ ] 能计算 RTT

### 任务 2.3: 实现探测定时器
**文件**: `mesh/mesh.go`
**描述**:
- 启动定时任务（每 10 秒）
- 遍历所有 peer，发送探测包
- 更新 peer 的质量指标

**验收标准**:
- [ ] 定时器正常工作
- [ ] 所有 peer 都被探测
- [ ] 质量指标定期更新

### 任务 2.4: 测试验证
**环境**: QG + JF
**描述**:
- 部署 Phase 2 代码
- 查看日志，确认探测包发送/接收
- 查看 API，确认质量指标正确

**验收标准**:
- [ ] 日志显示探测包发送/接收
- [ ] API 返回正确的 RTT 和丢包率
- [ ] 质量指标定期更新

## Phase 3: 智能选路（优先级：P2）

### 任务 3.1: 修改选路逻辑
**文件**: `mesh/mesh.go`
**描述**:
- 修改 `HandleOutboundPacket` 的选路逻辑
- 使用 peer 的质量数据（RTT、丢包率）
- 实现基于质量的选路策略

**验收标准**:
- [ ] 选路考虑质量数据
- [ ] 优先选择 RTT 小的 peer
- [ ] 过滤丢包率高的 peer

### 任务 3.2: 实现选路策略配置
**文件**: `config/config.go`, `mesh/mesh.go`
**描述**:
- 添加配置项：`routing-strategy`（quality | hop-count | random）
- 添加配置项：`quality-weight`, `hop-weight`
- 根据配置选择选路策略

**验收标准**:
- [ ] 配置项生效
- [ ] 不同策略表现不同
- [ ] 默认策略是 quality

### 任务 3.3: 测试验证
**环境**: QG + JF → 所有环境
**描述**:
- 部署 Phase 3 代码到 QG 和 JF
- 测试不同选路策略
- 验证性能提升
- 部署到所有环境

**验收标准**:
- [ ] QG + JF 验证通过
- [ ] 所有环境部署完成
- [ ] 性能有提升（延迟降低）

4. 修复后重新部署

## 风险

1. **IPIP 封装开销**：每个包增加 20 字节，影响 <2%
2. **兼容性问题**：旧节点不支持 IPIP，需要向后兼容
3. **探测包开销**：每 10 秒每个 peer 一个包，影响 <1%
