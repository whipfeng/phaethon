# Mesh 吞吐测量与汇报规范

适用范围：phaethon mesh 的吞吐 / 延迟对比测量与结果汇报。目的只有一个——让数字可比、可复现，
避免把链路漂移或测量口径差异当成代码收益。

## 1. 成对测量，口径必须一致

- 每个对比场景同时给出 **OS 级（不经过 mesh）** 和 **mesh 级** 两条数据，放在**同一行**，
  并标 `mesh/OS` 比值；不要分两段列表让读者自己对照。
- 必须保持一致：方向（pull/push）、并发流数、文件大小、端点类型（系统 sshd vs 内建 SSH）、
  大致时间窗口。任何一项不同，数字不可比。

汇报格式示例（数值仅演示格式，非当前基线）：

| 对比段 | OS 级（不过 mesh） | mesh 级 | mesh/OS |
|---|---|---|---|
| 单跳单流 | 2.7MB/s（公网 sshd） | 0.58~1.8MB/s（内建 SSH） | 0.2~0.7x |
| 单跳 8 流 | 10.2MB/s（公网 sshd） | 4.75MB/s | 0.47x |

## 2. 两跳也有 OS 级等价路径

两跳（A→B→C）不能说“没有 OS 基线”。用 SSH 跳板构造：

```bash
ssh -J root@<IP_QG_OS>:2222 -p 60002 layer4@<IP_JF_HT>
# 等价写法
ssh -o ProxyCommand="ssh -p 2222 root@<IP_QG_OS> -W <IP_JF_HT>:60002" ...
```

两跳 mesh 数据必须和这个 OS ProxyJump 基线成对比较。

## 3. 在当前窗口重新做基线

网络状态会漂移，不要拿几小时前的数字当今天的基线。每个数据点标注测量时间。

## 4. 旧数据不删，只追加 / 改状态

- 历史测量保留，新数据 append。
- 旧结论需修正时就地标注“已被 <时间点> 数据取代”或“受链路劣化污染”。
- 每次 A/B 记录：时间、版本 / commit、路径、流数、耗时、字节数、srtt / jitter、
  retransmits / DSACK 增量。

## 5. 同窗口交替跑

基线与实验各至少 3 次，尽量交替（A B A B），比较中位数，避免把链路漂移当成代码收益。

## 6. 每条数据显式标注“过不过 mesh”

- **OS 级**：系统 ssh / scp 直连公网 `IP:port`，不经过 TUN / phaethon / mesh。
- **mesh 级**：连 `*.phn` 或 mesh IP，走 TUN → phaethon → P2P 载体 → 对端 netstack。

两类数据不能混在一张表里而不说明口径。
