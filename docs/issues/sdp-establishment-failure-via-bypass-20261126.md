# SDP（SafeLink 零信任）经 QG 旁路网关建立失败（2026-11-26）

**创建时间**: 2026-11-26
**状态**: 已解决（2026-11-26 用户确认；按根因候选 1 方向处理——SDP 平台侧放行/调整，phaethon 链路无需改动）
**优先级**: 中

## 问题描述

办公区 LAN 用户（192.168.1.x，网关指向 QG 旁路 192.168.1.101）安装 SafeLink
（智掌易 UUSAFE 零信任 SDP）客户端后**无法建立连接**；QG 控制台 connlog 中
看不到到 SDP 网关地址（41.63.160.x）的请求。

## 环境与角色

| 节点 | 角色 |
|------|------|
| qgw（WQPC, 192.168.1.100, Win7） | wangqian 的机器，SafeLink **正常工作**（参照样本），默认网关 192.168.1.1 直连办公线路 |
| 失败用户机（如 192.168.1.207） | SafeLink 无法建立隧道，默认网关 = QG 旁路 |
| QG (192.168.1.101) | 旁路网关：FORWARD → tun0 → netstack → 规则分流 |
| MGMS_HT | h_tunnel → JF（udp:true），JF 位于移动网络内 |

## 规则与链路（QG 实测）

- TUN 时段规则：`MATCH,Company#TUN@08:15-12:00` / `@13:30-18:00` → Company → **MGMS_HT**；时段外 → `MATCH,DIRECT`
- SDP 分流段规则：`10.181.12.x/13.x → MGTB_NET`（MGTB_HT 链：h_tunnel → `10.181.12.8:9003` via WIN7_VPN）、`10.181.58.x/10.181.77.190 → WIN7_VPN`（SOCKS5 → qgw:7890）
- 41.63.160.x / 36.133.x / 39.156.x / 221.178.45.x 等 SDP 网关/业务地址**无专属规则** → 命中 MATCH,Company → MGMS_HT

## 关键实测（2026-11-26）

### qgw 参照样本（SafeLink 正常）

- SafeLink v2.0.7.1（2026-04-21 构建），服务 `SafeLinkSdpManager` + `ZhizhangyiSdp$SafeLink`
- 隧道适配器（wintun "Zhizhangyi Sdp Tunnel"）：105.168.3.104/32 + IPv6 2401:5100:2::365；内网 DNS 190.80.0.0（反解 nameless.gtt.co.gy——圭亚那 GTT）
- 分流清单：/32 主机路由 metric 1（10.137.200.x、10.181.x 多段、10.191.1.x、10.193.6.x、10.253.17.x、10.194.147.12、41.202-207.0.0/16 经 190.80.0.0、41.63.160.2/4/10/12、36.133.73.187、36.155.97.109、36.160.4.230、39.156.1.89/3.210、221.178.45.101/118/220）
- **隧道探活**：`nslookup www.baidu.com 190.80.0.0` 正常应答 → **qgw 隧道活着**
- 网关服务会话：`105.168.3.104 → 41.63.160.2:9081` 周期性短连接（TIME_WAIT 循环）；**41.63.160.x 为隧道内侧地址**

### 可达性矩阵（决定性）

| 目标 | 经 QG 旁路（→MGMS_HT→JF） | 办公线路直连（192.168.1.1）|
|------|---------------------------|----------------------------|
| 41.63.160.2 TCP:9081 | ✅ 通（RTT 5ms，JF 站点近端） | ❌ 100% 丢包 |
| 112.25.126.99 ICMP | ✅ 通（18-50ms） | ❌ 100% 丢包 |

**结论：SDP 网关/承载地址全部是移动网络内部地址，办公线路路由不到；必须经 MGMS_HT→JF（移动网络内）这条路径。** 上午"41.63.160.x = 承载服务器"的判断有误——它只是隧道内侧的网关服务地址。**承载服务器已由用户确认为 `UDP 112.25.126.99:8888`（江苏移动段）**；wangqian（qgw）被分配的是另一个办公线路可达的网关，故其客户端不经旁路也能正常工作。

### 失败用户机（192.168.1.207）触发实测

- 触发 SafeLink 重连后，connlog 出现高频 UDP：**192.168.1.207 → 112.25.126.99:8888**（江苏移动段）——该用户组被分配的 SDP 承载服务器（已确认）
- **双向包都在**：eth1 上可见 `112.25.126.99.8888 → 192.168.1.207.<port>` 回包（5 个端口 6-23 包/端口）；（注：首次"单向流"判断系 `head -15` 截断造成，已修正）
- 但客户端持续以新源端口重试（几十个端口循环），**建立始终不完成**
- QG connlog：该 UDP 流 `status=ok`（仅表示转发成功，不代表应用层握手结果）
- 约 17:08 后 .207 静默（仅 ARP）——重试循环停止

### 出口 IP 对照

- 办公线路出口：36.152.39.58（移动）
- JF 出口：36.140.28.178（移动）
- 经旁路路径时，SDP 服务器看到的客户端源 IP = **36.140.28.178（JF 出口）**，而非办公线路出口

## 根因分析（候选，按可能性）

1. **零信任源 IP 策略**（最可能）：SDP 平台校验客户端公网源 IP；经旁路路径源变为 JF 出口
   36.140.28.178，不在该用户/该网关的授权源列表 → 服务端拒绝会话 → 客户端无限重试。
   参照：qgw（wangqian）的客户端不经旁路、源为办公线路出口 → 正常。
2. 客户端配置/凭证问题（该用户组的网关分配与 wangqian 不同：112.25.126.99 vs 办公线路可达的另一网关）
3. 链路对握手包的时序/分片影响（UDP 中继内容无关，可能性低）

## 修复方向（按根因确认后）

- 若确认源 IP 策略：平台侧将 JF 出口 36.140.28.178 加入授权源（或调整该用户组网关为办公线路可达地址，同 wangqian）
- 若为网关分配问题：平台侧调整
- 均为 SafeLink 平台侧操作；phaethon 侧（QG/MGMS_HT）链路本身已验证可达（ping/TCP 均 OK），无需改动
